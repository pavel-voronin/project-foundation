# Участие в Project Foundation

Стадия проекта — фиксация архитектуры. Полезные изменения сейчас: уточнение контрактов, исследования точек подключения PZ, сценарии совместимости и синтетические фикстуры. Реализация Vulkan начинается отдельным этапом.

## Локальная проверка

1. Установите JDK 17+ и Python 3.9+.
2. Выполните `python3 tools/check_architecture.py`.
3. Выполните `./gradlew check`; на Windows — `gradlew.bat check -PpythonExecutable=python`.
4. Для чистой сборки: `./gradlew clean check`.

Gradle 9.2.1 и его дистрибутив зафиксированы wrapper-файлами. Внешних Maven-зависимостей сейчас нет. Проверка архитектуры запускается и отдельно от JVM: она проверяет граф модулей, импорты границ и локальные ссылки Markdown. Сборка не тестирует GPU и не подтверждает работу с PZ.

Java 17 выбрана для простого независимого каркаса. Версию JVM игрового адаптера, LWJGL и native-библиотек зафиксируем после инвентаризации выбранного билда. Не устанавливайте второй LWJGL core в процесс игры без проверки совместимости.

## Изменения контрактов

Публичные контракты пока `draft`. Изменение владения ресурсами, порядка событий, модели потоков или совместимости сопровождается ADR в `docs/decisions` и обновлением зависимых документов. Для изменения модулей редактируйте `architecture/modules.json`; Gradle использует этот файл напрямую.

Перед добавлением зависимости определите, какая граница от этого меняется. Классы PZ остаются внутри адаптера, Vulkan — внутри бэкенда и специального interop-модуля, GLFW — внутри платформенного адаптера. Документация на русском; код и Conventional Commit сообщения — на английском.

## Публикация

Не включайте локальные игровые JAR, декомпилированные классы, ассеты и Workshop-моды. Новая сторонняя зависимость требует записи с лицензией, версией и происхождением в `THIRD_PARTY_NOTICES.md`. Результаты проверки на пользовательском моде публикуйте только при наличии права раскрывать соответствующие файлы; для открытых тестов предпочтительны собственные фикстуры.
