# ADR 0001: границы модулей

Дата: 2026-10-21. Статус: accepted.

## Контекст

Смешивание игровых объектов, вызовов GPU и системного окна затрудняет замену рендера и поддержку платформ. Foundation должна допускать как внешнюю интеграцию, так и будущее включение в саму игру.

## Решение

Отделить foundation runtime, platform, graphics, presentation и адаптер PZ. Все знания классов и версии игры принадлежат адаптеру. Сборка из компонентов находится в референсном моде. Граф сборки задаёт `architecture/modules.json`. SPI бэкенда находится в переносимом graphics API.

Сначала фиксируются контракты и package scaffolds на Java 17. Gradle 9.2.1 используется только для сборки. Конкретные signatures, runtime JVM, LWJGL и loader strategy выбираются после исследования PZ. Ни одной GPU-реализации в начальном каркасе нет.

## Последствия

Те же библиотеки можно подключить из TIS напрямую, заменив патчи штатными вызовами. Команды старого рендера могут временно переводиться адаптером, но не становятся публичной GL-подобной моделью. Выделение новых подсистем требует отдельного контракта; универсальный движок заранее не строится.
