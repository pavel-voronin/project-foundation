# Проверка корректности

## Сейчас

`python3 tools/check_architecture.py` проверяет каталог модулей, отсутствие циклов и запрещённых зависимостей/импортов, наличие каркаса и локальные ссылки Markdown. `./gradlew check` дополнительно компилирует все package scaffolds. CI настроен для Windows, Linux и macOS. Эти проверки не тестируют GPU, установку PZ или совместимость реальных модов.

## До реализации адаптера

Определяем точный build/revision игры и baseline. Матрица обычных модов задана в [контракте совместимости](mod-compatibility.md). Сценарии используют собственные synthetic fixtures; игровые материалы остаются локальными.

## Будущие обязательные сценарии

| Область | Сценарии и свидетельство |
|---|---|
| Изображение | Детерминированная сцена, одинаковые камеры и время; diff с эталоном; осмысленные допуски для текста и driver-dependent rasterization |
| Граф | Validation layers, synchronization validation, negative cases для циклов/гонок/несовместимых usage |
| Ресурсы | Повторные загрузки/выгрузки, resize, GPU completion, память после прогрева и возврат к устойчивому состоянию |
| UI | Fonts, clipping, tint, blend/stencil, drag/drop, focus, hit testing, масштаб, локальные игроки |
| Обычные моды | События, gameplay effects, content, assets и ванильные drawing callbacks без изменения исходников мода |
| Сохранения | Копия мира: vanilla → Foundation → vanilla; `modData` и игровые schemas сохраняются |
| Сеть | Клиент/серверные моды, команды, integrity checks, dedicated server без графической инициализации |
| macOS | KosmicKrisp, Apple Silicon, macOS 26+, чистая установка, Retina, fullscreen, сон/возврат |
| Межплатформенность | Нативные Vulkan-драйверы Windows/Linux; одинаковые смысловые результаты сцен |
| API модов | Минимум два независимых расширения; portable и native пример; конфликты providers выявляются |
| Сбой | Прерванная инициализация, несовместимый билд, отсутствующий driver/feature, device loss и ошибка расширения |

Frame replay исполняет только собственные сериализуемые визуальные данные и не повторяет игровые/Lua callbacks. Захваченные пользовательские кадры могут включать частные assets или имена: не публикуются автоматически.

## Диагностика и производительность

Диагностика включает frame/task/owner/resource IDs, выбранный backend, фактический драйвер, capabilities и revision адаптера. Неопределённая метрика не показывается нулём. CPU game, CPU render и GPU time измеряются отдельно; фиксируются frame-time distributions, stalls и объём памяти.

FPS не является go/no-go для начала проекта. Однако регресс против заявленной конфигурации нельзя скрыть средним FPS или ссылкой на смену API. Бенчмарки публикуются с версиями и сценарием.
