Нет обещанных дат. Каждый этап заканчивается проверяемым результатом. Совместимость обычных модов проверяется при переносе каждой подсистемы, а не после завершения Vulkan-рендера.

## Первые задачи этапа 1

1. Выбрать точный билд PZ; записать revision/hash и версии Java/LWJGL/GLFW.
2. Установить способ локальной интеграции без распространения игровых файлов.
3. Снять каталог GL-путей, включая раннюю инициализацию, `GenericDrawer`, texture/model atlases, framebuffer, Lua UI, thumbnail и video.
4. Зафиксировать ванильную фазу и поток каждого callback: вызовы не должны удваиваться при записи и воспроизведении.
5. Создать собственные fixtures для gameplay/content, UI, world draw, карт/tiles, texture/model assets и saves.
6. Получить baseline ванильной игры на целевых платформах.
7. Записать схемы визуальных данных и первые Java-сигнатуры на основе найденных потребителей.

## Правила перехода

Меню не считается доказательством работы мира. Минимальный мир не считается полнотой. Неизвестные GL-пути остаются блокирующими для утверждения полной замены OpenGL. Штатные и модовые визуальные сценарии закрываются вместе.

Промежуточный debug-мост к старому GL допустим только как обозначенный инструмент разработки. Выпуск Vulkan-пути не должен требовать живого GL-контекста для ранней загрузки, штатных assets или обычного UI. Fallback между бэкендами возможен до старта сессии; не используем per-pass fallback после submit.

## Отложенные задачи

Поддержка Intel/старой macOS, другие графические бэкенды, независимый внешний submit, горячая перезагрузка Java-модов и выделение подсистем логики рассматриваются отдельными решениями. Они не блокируют современный Mac-путь и не размывают обязательства перед обычными модами.
