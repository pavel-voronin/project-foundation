# Совместимость с обычными модами PZ

Совместимость — обязательное требование Project Foundation. Существующему моду, который использует ванильные игровые и визуальные контракты, не нужен Foundation SDK и не требуется переписывание ради нового графического бэкенда.

**Текущий статус: поддержка ещё не реализована и не проверена.** Этот документ определяет условия будущего выпуска и границы обещания; он не объявляет совместимость со всем Steam Workshop.

## Матрица контрактов

| Категория | Цель | Где сохраняется поведение | Проверка |
|---|---|---|---|
| Lua gameplay, события, callbacks | Без изменений для мода | Ванильный Lua runtime и события PZ | Порядок, аргументы, кратность вызовов, игровые эффекты |
| Предметы, рецепты, профессии, sandbox, scripts | Без изменений | Существующие игровые загрузчики | Загрузка и поведение синтетического content-мода |
| Карты, tiles, texture packs | Без изменений поддерживаемых форматов | Загрузчики PZ + визуальные converters | Пользовательские tile/texture assets и streaming |
| Модели, одежда, анимации, attachments | Сохранение ванильного контракта | PZ assets → ресурсы presentation | Позы, альфа, композиция атласов, lifecycle |
| Lua UI, окна, инвентарь, drawText/drawTexture | Без изменений для обычного UI-мода | Ванильные layout/input + фасад UI-команд | Clipping, tint, порядок, fonts, focus, picking, DPI |
| Ванильные world/UI render-callbacks | Сохранение наблюдаемой семантики | Адаптер записывает графические команды | Timing, transform, blend, stencil и render targets |
| `modData`, saves, multiplayer commands | Сохранение данных и поведения | Игровая логика PZ | Round trip, загрузка без Foundation, клиент/сервер |
| Java-моды вне рендера | Совместимость с проверенными контрактами выбранного билда | Ограниченная область патчей адаптера | Репрезентативные hook/override фикстуры |
| Прямые LWJGL/OpenGL-вызовы, GL IDs, private FBO | Требуется миграция | Foundation API либо Vulkan interop | Явное объявление конфликта/интеграции |
| Подмена renderer/core классов, собственные 3D renderer | Явная интеграция | Согласованный provider и API Foundation | Проверка конфликтов и отдельные сценарии |

Не все реальные моды укладываются в одну строку: gameplay-мод может содержать собственный GL-hook. Классифицируем используемые контракты и наблюдаемое поведение, а не название мода. Общий OpenGL-эмулятор и автоматическая поддержка произвольных Java overrides в эту задачу не входят.

## Фасад ванильного рисования

Старый вызов рисования сначала сохраняет свою ванильную семантику внутри адаптера, затем преобразуется в команды Foundation. Сохраняются UV/subtexture, tint и alpha, шрифты, scissor, stencil, transforms, UI/world order, масштаб и активный локальный игрок. Нельзя объявить UI совместимым, проверив только отображение одной текстуры.

Render-callbacks вызываются в прежней игровой фазе с ожидаемыми аргументами. GPU-поток исполняет записанные данные; он не вызывает Lua повторно. При frame replay игровые callbacks вообще не выполняются.

Ошибки неизвестного render operation не скрываются пропуском. До использования соответствующего пути нужна реализация, документированное ограничение либо явное сообщение о несовместимости. Никакого незаметного перехода на OpenGL внутри кадра.

## Сохранения и сервер

Foundation не меняет schema игровых сохранений и не подменяет `modData`. Собственные кеши и настройки отделены, имеют версию и могут быть удалены без потери мира. Мир и данные обычного мода должны загружаться ванильной игрой после отключения Foundation; это проверяется на копиях сохранений.

Dedicated server не инициализирует окно, Vulkan и визуальные расширения. Серверная логика и сетевые команды обычных модов сохраняются. Client-only статус, проверки целостности файлов и правила multiplayer выбранного билда необходимо подтвердить исследованием; совместимость не предполагается автоматически.

## Выпуск

Перед утверждением поддержки билда обязательны:

1. Синтетический пакет обычных модов: gameplay/content, карта/tiles, texture/model assets, Lua UI и render callbacks.
2. Следы событий и игровых эффектов в ванильной игре и Foundation совпадают для сравниваемых сценариев. Диагностические различия не меняют порядок callbacks.
3. UI и rendering fixtures проверены на Windows, Linux и Apple Silicon/macOS 26+.
4. Save round trip, отключение Foundation, multiplayer и dedicated server проверены отдельно.
5. По согласованному набору существующих модов опубликованы версии, сценарии и реальные результаты без незаконного включения их файлов в репозиторий.
6. Прямые GL-моды и конфликтующие renderer replacements имеют понятный путь миграции и диагностику.

Пустой список найденных конфликтов не доказывает совместимость. Неизвестные/непроверенные случаи помечаются отдельно. Автоматический поиск GL-ссылок — подсказка, не полный детектор динамически загружаемого кода.
